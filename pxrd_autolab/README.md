# PXRD AutoLab bridge presets

This package contains two fixed entrypoints for the local GitHub-to-GPU bridge. Its current scientific A/B path is fail-closed: `run.py` produces an executable preflight report and exits blocked until the measurement-aware evidence gates and a reviewed training backend exist. It does not contain a substitute training loop, use the old clean-reference loss, or certify any result.

## Presets

| Preset | Entrypoint | Purpose |
| --- | --- | --- |
| `forward_ab` | `run.py` | Check the reviewed BaTiO3 exploratory-pilot config, emit machine-readable scientific gate status, and refuse training while required gates/backend are missing. |
| `forward_speed_benchmark` | `benchmark_gpu.py` | Run actual CUDA float32 matrix multiplications and record device, CUDA/PyTorch versions, free/total VRAM, and measured throughput. It is a hardware benchmark, not scientific training. |

The bridge binds each preset to one exact config path and SHA256. GitHub Issues cannot choose a Python executable, script, shell command, arguments, or replacement config. The bridge selects Python from the administrator-controlled `AI4SCIENCE_GPU_PYTHON`, the documented local venv default, or its own interpreter.

## A/B gate contract

`forward_ab` is intentionally blocked until machine-readable PASS evidence generated by reviewed executable tests exists for all of the following:

- structure and independent reference provenance;
- independent full-spectrum parity;
- measurement-aware expected-profile behavior;
- autograd against finite differences;
- q/eta identifiability;
- non-oracle nuisance estimation;
- split and leakage safety.

The current `physics_gates.py` reports `BLOCKED_MISSING_EVIDENCE` for every gate. A config or Issue flag cannot satisfy a gate. `REVIEWED_TRAINING_BACKEND` is unset, so the pilot reports `BLOCKED_MISSING_IMPLEMENTATION`, writes outputs, and exits with code 3. The source-controlled pilot scope is one exploratory BaTiO3 CIF with a 7,200-second experiment budget; that budget does not set the bridge process timeout. Even a future passing pilot would not establish unseen-structure generalization or real-experiment refinement.

The current run emits `run_manifest.json`, `gate_report.json`, `metrics.json`, and `TECHNICAL_REPORT.md`. It makes no performance claim and does not alter frozen V9 results.

## CUDA benchmark

`benchmark_gpu.py` allocates CUDA matrices from the fixed config, performs warmup matrix multiplications, times synchronized CUDA events, and reports median seconds and TFLOP/s per configured size. It reports a blocked result if PyTorch/CUDA is unavailable or free VRAM is below the configured floor. It never substitutes a CPU measurement. A successful benchmark says nothing about the validity or readiness of scientific training.

## Local checks

From the repository root, run the CPU-only tests with the bridge's approved Python:

```powershell
& 'E:\AI4science\.venvs\xrd_test\Scripts\python.exe' -m unittest discover -s research_bridge/tests -v
& 'E:\AI4science\.venvs\xrd_test\Scripts\python.exe' -m unittest discover -s pxrd_autolab/tests -v
```

These tests do not start CUDA training. The bridge can publish bounded, sanitized text result bundles to a dedicated `bridge-results/<run_id>` branch and open a Draft PR; publication is not a scientific review or certification and is never auto-merged.
