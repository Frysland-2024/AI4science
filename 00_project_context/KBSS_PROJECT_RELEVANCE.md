# KBSS 思想吸收笔记

更新日期：2026-07-13

## 定位

KBSS 只作为当前项目的外部方法思想参考，不作为代码依赖、模型组件、数据来源或工程模板。

源码保留在代码仓库区，仅用于以后查阅原论文实现：

`02_code_repositories/github_archives_extracted/KBSS-main/`

## 值得吸收的核心思想

KBSS 关注的是：当标注数据有限时，如何利用更多未充分标注的数据，并要求模型对同一个对象的不同视图保持预测稳定。

它的思想链条可以概括为：

1. 同一个对象生成弱视图和强视图。
2. 弱视图的预测作为强视图的参考。
3. 只有模型足够有把握时，才相信这个伪标签。
4. 在正常监督目标之外，要求不同视图的预测保持一致。

## 对当前 XRD 项目的启发

当前项目也研究“同一晶体在合理测量扰动下，模型是否保持稳定”。因此可以吸收同一个高层原则：

> 对标签不应改变的视图变化，模型不应因为视图变化而随意改变判断。

但当前项目中的“视图”必须来自有物理依据的 XRD 测量扰动，例如峰位偏移、峰展宽、噪声和背景变化。KBSS 本身的晶体结构视图变化不能直接当成 XRD 扰动依据。

## 不吸收的部分

- 不移植 KBSS 的代码实现。
- 不引入它的晶体图网络、数据集或材料属性任务。
- 不照搬它的具体伪标签阈值、损失权重或训练流程。
- 不用它的实验结果替代当前项目自己的物理证据和公平对照。

## 代码级审计结论

本地公开快照不是可直接运行的完整工程，也不应作为 V6 的代码模板。静态检查发现：

- `dataset/data_unseen.py` 的弱视图主要是重排原子顺序，不等于论文描述的原子位移增广。
- 强增广的移动尝试与交换控制流存在覆盖问题，原子交换也没有明确使用不重复采样。
- `kbss_train.py` 读取无标签视图时存在索引疑点，按返回顺序可能没有真正使用强视图。
- 增广在数据集初始化阶段缓存，属于固定离线双视图，不是每个训练步重新采样的动态增广。
- APF 的高斯平滑概率计算与后续 mask 使用的输出没有形成清晰闭环。
- 路径、GPU、CPU 数量、`.cuda()`、数据文件、学习率和实验重复次数存在硬编码或缺失。
- 没有可直接迁移到 V6 的样本预算曲线、完整数据下载流程、测试体系或可复现运行入口。

这些判断来自本地源码快照，报告中应写成“当前公开快照的静态审计结论”，不应推断作者未公开版本。

## 与当前代码的关系

当前 `xrd_robustness` 没有导入 KBSS 模块，也没有复制其 DimeNet++、APF、Lennard--Jones 验收或伪标签损失。V6 只吸收“同一对象的不同合理视图应保持预测稳定”这一高层思想，并用有物理依据的 PXRD 测量扰动重新实现。

## 最终判断

KBSS 对当前项目有价值，但价值仅在于提供“弱/强视图 + 置信度筛选 + 一致性约束”这一套思考框架。当前项目应把这个框架重新解释为 XRD 测量鲁棒性问题，而不是把 KBSS 工程搬过来。
