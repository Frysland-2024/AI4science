# 2026-10-22 与谭启导师的 PXRD 汇报：方法设计与应用可信度之间的评价错位

**时间：** 2026-10-22 晚；于 2026-10-23 根据项目负责人的回忆整理。  
**资料性质：** 事后个人复盘，**不是逐字会议记录，也不是导师确认过的观点摘要**。  
**状态：** HISTORICAL / COMMUNICATION LESSON。本文不修改已冻结的训练、测试、论文结论；导师提出的扩大训练与论文对标尚不能据此写成已批准、已完成的科研任务。

## 1. 汇报原来的设计思路

汇报沿用项目展示 PDF 的叙事顺序：

1. 先讲方法设计：利用在线模拟器保留的**同母结构（same-parent）关系**，使用 JS prediction consistency 把关系监督引入 PXRD 七晶系训练。创新对象不是 JS 散度本身，而是**同源测量信息的发掘、监督任务设计及受控方法验证**。
2. 再讲五类物理/测量扰动、晶体数据库与数据集、训练流程。
3. 最后展示 Dynamic JS 相对 Dynamic ERM 的性能增益、真实域验证及相关图表。

项目负责人希望讨论的主要是**为什么提出这一方法、训练流程如何设计、什么受控证据说明它优于普通训练**，借此呈现自己独立进行科研问题设计、试错、纠偏与验证的过程。

## 2. 导师的追问与沟通中暴露的具体错位（按项目负责人复述）

### A. 对扰动的物理合法性及覆盖范围的质疑

导师关注：所谓峰移、展宽、背景等扰动究竟是真正对应材料与测量物理，还是仅对一维曲线套数学函数？现实实验中的**温度、成分**是否考虑？当前模型对真实实验情形到底能解释多少？

**复盘判断：** 这不是“导师不懂机器学习”。它在询问模拟任务的物理前提和真实适用范围。当前五扰动均有文献/机制锚点，但属于受控近似而非所有真实实验因素的完整生成模型。既不能说未加入温度/成分就没有科学性，也不能把现有扰动夸大成覆盖所有实验域变化。

### B. 柱状图的比较对象被误读

讨论柱状图时，导师**最初把图中的比较对象理解为“别人的原模型”**；项目负责人澄清：自己引用/对照的是**他人提出的原方法/训练思路，并不是直接拿对方发表的原模型权重或原论文性能与本项目模型作逐项同条件比较**。

随后导师追问：**这样的比较是否存在 bias（偏差），是否足够公平、可信？**

这一细节说明图表的比较对象、复现范围、实施条件及公平性，没有在第一眼就传达清楚，导师因而从证据有效性的角度提出质疑。不能把这次追问简单记录为导师不理解创新。

需要长期保留的区分：
- **同实验协议内的受控消融/方法对照**：当前 Dynamic ERM 与 Dynamic JS 固定母结构、双视图暴露、扰动分布、ResNet backbone、训练预算及测试标准；可以支持“在这个协议下同源 JS 监督的边际收益”。
- **跨论文的绝对性能比较**：若直接对照发表论文的分数，而数据、标签、划分、扰动、实际谱来源或指标不同，便可能有不可忽略的 apples-to-oranges bias；不能把这样的数字并列当作公平 head-to-head。
- **他人原方法、他人公开模型、他人论文报告指标** 是三个不同对象。PPT 图例、标题及讲稿必须写明究竟借鉴了什么、重新实现了什么、哪些没有复现。

### C. 相对方法增益 vs 绝对性能、文献基准与真实数据

导师后续持续追问：模型**绝对跑分有多高**，和**现有发表论文**相比处于什么水平，能不能**经得起真实实验数据集检验**。按负责人复述，他建议进一步扩大训练/数据规模、开展论文对标，使结论在外部研究者看来更加 **trustable**。

而负责人当时强调的是：在明确的同母结构监督假设下，Dynamic JS 是否**相对同设置的 ERM**获得改进；为何是这种监督关系带来的收益。这和外部绝对性能问题不相同。

历史已完成结果应原样保留，不能因为此次汇报而回写或篡改：模拟 Test 中单因素 OOD Macro-F1 约 **0.6507 → 0.7053**；RRUFF-301 的 K=5 few-shot locked-test Macro-F1 约 **0.3555 → 0.4099**；CNRS-318 zero-shot Macro-F1 仍很低。这些是**方法增益的证据**，不是广域真实 XRD 已达到可部署精度的证据。

## 3. 对于这次不顺利，应该怎样理解

从负责人的主观感受看，打击最大的**不是**导师希望加大训练本身，也**不是**被指出绝对分数不足，而是：几个月以来围绕 same-parent provenance、方法设计、失败分支取舍、公平实验与数据效率投入的独立研究思考，**未在这次交流中被充分理解和讨论**；导师似乎主要知道“用了一个优化手段”，尚未进入“为什么这样设计、怎样与普通方法有本质差异”的讨论。

然而，不能由单次汇报推断：
- 导师认为算法方法研究无价值；
- 导师不懂 ML；
- 项目研究路线已经失败；
- 因为导师没有深入讨论 JS，方法贡献就不成立。

更审慎的判断是：双方采用了不同的**进入问题的顺序和证据标准**，而 PPT 对“引用他人方法还是他人模型”的图表表达又增加了误读和公平性质疑。

## 4. 应保留的两条证据链

| 方法有效性（method validity） | 外部/应用可信度（external and application credibility） |
|---|---|
| 明确 same-parent relationship 的新监督信息来自哪里 | 明确哪些扰动是真实测量效应，哪些结构/状态变化未覆盖 |
| 匹配 ERM/JS 的数据暴露、模型、预算、split、seed | 与相关发表工作的同任务/同指标可比性，严格说明不可比之处 |
| 报告相对 Macro-F1、多个 seed、OOD 及 few-shot | 报告真实谱上的**绝对** Macro-F1/Accuracy、错误类型与适用边界 |
| 讨论为什么方法可能有效，以及尚未证实的机制 | 讨论扩大母结构规模后是否仍然有效、是否真正具备应用价值 |

**核心教训：** 相对方法收益不等于领域 SOTA，也不等于应用可用；绝对性能不够高，也不能直接抹去受控方法比较的科研价值。两类问题必须分别回答并在汇报中连接起来。

## 5. 下次汇报及未来科研习惯：有条件采用，不自动修改原协议

1. **先定义物理问题和边界**：哪些变化仅影响 measurement realization，哪些可能改变结构或晶系标签。温度与成分可能引起 `s=s(T,c)` 及相变，不能无条件视为 label-preserving nuisance。
2. **给所有比较图明确身份标签**：原论文方法概念、自己在统一框架内的复现基线、对方原模型、以及跨论文文献数字分开标注；讲清 bias control，避免图表暗示不存在的公平跨论文对照。
3. **先交代当前绝对性能及其局限，再说明方法增益**：不能只说“提升 +x pp”，也不能只说“分数低因此无方法价值”。
4. **若将来拓展规模与 benchmark**，预先定义公平对比条件，公开数据划分、指标和计算预算；新实验另立协议，现有冻结模型与 Test 记录原样保留。把导师建议标为 **SUGGESTED / NOT YET EXECUTED**，而不是把加数据和追 SOTA 偷偷写成当前论文的已完成结论。
5. **研究训练层面的修正**：不放弃方法研究的兴趣，但要学会从材料/测量物理与已有传统工作流出发，再说明为什么需要 ML 方法；能同时回答“为什么这项监督更好”和“真实世界能否用”。

## 6. 对未来申请叙事的意义（不得伪造成功结果）

这次交流是从 FerroAI 走到 PXRD 研究过程中一个重要的认知转折：过去负责人更习惯优先展示**算法与训练流程的设计逻辑**；这次意识到，跨领域研究中需要同时建立**物理合理性、方法比较公平性、真实域绝对性能**三条可信证据链，并学会对不同背景的研究者准确解释“方法”与“模型”的区别。

日后申请文案可以如实描述为：**一次未能充分沟通方法贡献的导师汇报，促使我重新思考如何使 ML 创新不仅在内部对照中成立，也经得起具体科学测量任务与外部基准的审视。** 这是研究观念演变，而非声称已通过后续外部检验。
