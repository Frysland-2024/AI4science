## 1. 汇报前：我到底想展示什么

过去数月，从 FerroAI 逐步转向 PXRD，我在研究中越来越关注「如何构思并验证一个机器学习方法」，而不仅是使用训练好的网络完成分类。当前项目的正式定位仍是**PXRD 七晶系监督分类中的模拟器同母结构关系监督**。

这条思路不是「我发明了 JS divergence」。我的主要研究构思是：

1. 在线模拟器从母晶体结构生成不同条件下的谱图，天然知道每条谱来自哪个 **parent structure**；
2. 同母结构生成的谱图具有比「同晶系类别」更强的关系信息，前提是变化保持标签；
3. 把这种 **shared parent identity → measurement equivalence → relationship supervision** 显式纳入监督设计；
4. JS prediction consistency 是落实关系监督的既有算法工具；
5. 在统一母结构、模拟视图、backbone、训练预算、拆分和评价口径下，把 Dynamic JS 与 Dynamic ERM 作**受控比较**；
6. 通过模拟 OOD、RRUFF few-shot、CNRS zero-shot 以及独立母结构预算曲线，检验额外监督能带来什么，不能带来什么。

项目负责人强调：**整体研究方向、方案规划、实验问题与验证设计主要由自己主导构思**；合作者在工程实现、运行、数据整理及辅助建议方面提供支持。这是负责人的角色陈述，不在此文件中据以裁定正式论文署名。

这套研究叙事以「问题设想—训练方案—方法对照—增益解释」为中心。汇报 PDF 依照这一偏好，先介绍方法创新，再介绍扰动和数据集，最后呈现图表及真实域结果。负责人本来期待导师能够理解自己**为什么提出这个方法、为什么这样设计实验、经过了怎样的判断和取舍**。

## 2. 当晚的实际交流：从第一部分开始的错位

以下事实均按负责人复述，不把对导师心理动机的推测写成客观事实。

### 2.1 算法、训练流程的介绍：双方关心的起点不一样

我讲的是 ML 算法优化、额外监督、训练流程和创新动机；导师反馈更集中于**模型最后能达到多高的绝对性能、能否应用、其他发表工作达到什么水平**。

负责人的原意不是声称「新发明了一种 JS 算法」，而是要解释如何从真实科学数据生成过程提取之前未被普通类别标签利用的监督关系。会后感觉，导师知道我采用了某种优化手段，但没有充分进入这项优化**究竟改动了学习问题的哪个部分、为什么要这样设计**的讨论。

### 2.2 扰动部分：我把它当训练变量，导师把它当材料科学命题

我介绍峰移、峰展宽、择优取向、背景、计数噪声及模拟数据集时，思考重点是：

- 这些变化如何形成同一母结构的不同 measurement views；
- 如何保障 label-preserving pair，生成可控的模型训练样本；
- 怎样在匹配的数据和计算预算下验证关系监督的效果。

导师关心的却是：

- 这些扰动是否真的来自材料或测量物理，而非随意给曲线套数学公式；
- **温度、成分**等条件是否纳入模型；
- 所选择的扰动能在多大程度上代表真实 XRD 实验；
- 对实际材料表征而言，这样建模是否成立、是否足够。

在那一刻，我已经意识到双方的**出发点/思考角度不一样**，但并没有在汇报中迅速切换到对方的视角去重新解释。会后与朋友的聊天中，我将此归纳为自己的「思维惯性」：习惯先从可迁移的算法与实验框架着手，而不是首先沿材料与测量机制纵向追问。

本项目文献证据见 [PXRD_PERTURBATION_EVIDENCE.md](PXRD_PERTURBATION_EVIDENCE.md)。当前五类扰动有物理机制与文献数值锚点，但属于**有意限定范围的近似模型**：例如全谱统一 2θ 零点偏移不等于每个峰独立平移，也不等于所有温度、应变、成分引起的晶格变化；标量 FWHM 也不是完整的角度相关/微结构展宽模型。**有物理基础，不等于已完整复现实验世界。**

特别要区分两类变量：

- **测量条件/部分制样条件变化**：可在假设母结构与晶系不变时建模为不同观测视图；同源一致性有明确前提。
- **材料状态或组成变化**：温度、成分有时引起连续的晶格参数变化，有时改变相与对称性；是否保持晶系标签必须逐例论证，不能无条件作为 same-parent label-preserving augmentation。

因此，导师的质疑是有价值的**任务范围与物理假设检验**，不是仅凭一句「公式有文献」就全部解决；但未纳入全部材料变量也不自动否定当前限定任务的科学意义。

### 2.3 柱状图：他人「原方法」被听成「原模型」，随后出现 bias 追问

在柱状图处，导师起初以为其中比较的是**别人的原模型**。我随即说明，借鉴或对照的是**别人的原方法/训练思路**，并非直接使用其已发表的模型权重或把其论文报告数字当成本项目的同条件成绩。

导师继而追问「这样比较有没有 bias」，随后继续强调绝对性能与外部可信度。

这个插曲不应该被写成简单的「导师不懂」。更准确的复盘是：

- **我心里的比较单位：** 在同一实验环境下，把两种训练方法拿来做公平控制变量的对比；
- **导师当时理解或试图核实的比较单位：** 你是否与别人发表的模型作了真正可比的性能对照；相较现有研究，你的结果凭什么值得信任；
- **沟通问题：** 图表没有立即让听众分清「文献提出的方法」「我们在统一协议下实现的方法基线」「别人发表的具体模型」「别人论文中的分数」四种截然不同的对象。

当前 Dynamic ERM 与 Dynamic JS 的受控比较本身针对**方法增益**，不能因此宣称达成了对他人发表模型的公平 head-to-head；真正的跨论文比较必须核实任务、晶系标签、数据来源、split、真实/模拟域、测量条件、指标及实验预算，明确哪些只可作背景参照。

### 2.4 结果部分：相对优势与绝对性能之间的落差

我着重展示：在同样结构数据库和训练条件下，增加关系监督后有没有明确的相对改进，以及多 seed、OOD 和 few-shot 证据能否支持这一研究判断。

导师则持续追问：

- 最终模型的**绝对性能**到底是多少；
- 与已经发表的 PXRD 相关论文相较如何；
- 数据规模能不能继续扩大、模型能不能继续提高；
- 是否能经受真实实验数据的验证，使其他人认为结果是 **trustable**。

导师建议进一步扩大训练并开展现有发表论文基准对标。按负责人口述，这并非导师明确表示「算法优化没有意义」，更像是在设置其认为足以认可研究结果的证据门槛。

现有记录不能模糊的事实：

- 模拟单因素 OOD Test Macro-F1，Dynamic ERM 约 **0.6507**，Dynamic JS 约 **0.7053**，5/5 matched seeds 正增益；
- RRUFF-301 few-shot K=5 locked-test Macro-F1 约 **0.3555 → 0.4099**；
- CNRS-318 zero-shot 的绝对表现依然低，不能表述为已经解决了真实 XRD 自动分类；
- 已完成的母结构预算补充实验在多个结构量级观察到 JS 相对 ERM 的增益；但并**未**给出得到严格支持的「节省多少母结构」定量结论。

这些支持「**在既定实验协议中，关系监督可提供增量效益**」，还不足以单独支持「**模型达到发表文献中的最好绝对性能**」或「**真实应用可以直接部署**」。

## 3. 「思考角度不同」到底是指什么——会后讨论得到的更准确解释

最初我用「研究方向对不上」「站的角度不一样」描述，之后又说自己总在**横向思考**，而谭启是在一个领域内**纵向深入**。会后与 AI 反复澄清后，这一表述更具体了。

| 维度 | 我当时的自然思考起点（横向、方法驱动） | 谭启在本次交流中表现出的关注起点（纵向、领域问题驱动） |
|---|---|---|
| 先问什么 | 如何从物理模拟/数据生成机制构造更好的监督？ | 被模拟的材料和实验变化，真实吗、覆盖了什么？ |
| 基本研究对象 | 训练关系、数据流、模型学习行为、实验设计 | 物理现象、谱图与材料状态的对应、识别任务本身 |
| 对「创新」的第一反应 | 数据利用方式、监督构造、控制变量后方法优于 baseline | 是否改善现实任务，能否超过或接近已发表的领域方法 |
| 对「可信」的第一反应 | 配对对照、公平预算、多 seed、增益机制 | 物理假设、外部文献 benchmark、真实谱、足够好的绝对分数 |
| 对扰动的提问 | 它是否提供合法的同源视图与 OOD 验证条件？ | 它在真实材料和实验中具体对应什么，遗漏什么？ |
| 对柱状图的提问 | 统一协议内新增监督的边际贡献是多少？ | 与哪篇论文/哪个模型比？有无 bias？ |
| 理想汇报顺序 | 方法想法 → 模拟和训练方案 → 实验增益 | 材料测量问题 → 物理与数据合法性 → 现有水平 → 模型绝对性能 → 方法说明 |

**这里的「横向/纵向」不是研究者优劣或学科智力差异。** 它描述两个正交的研究习惯：一个习惯提炼可迁移的方法与流程；另一个习惯深挖领域中的物理机制与实际能力。导师并未明确自称「只研究纵向问题」，此处仅是负责人基于此次问答对其关注角度的解释。

最重要的细化：

> **我问：「在一个已定义的 PXRD 模拟任务里，如何设计监督，使模型比标准训练更好？」**  
> **他问：「你定义的 PXRD 模拟任务与真实材料物理是否相符？即使比你的 baseline 更好，最终水平够不够可信？」**

这两问处于不同的论证层级。方法层不能代替科学任务层；科学任务层的批评也不能自动推翻已经成立的受控方法对照。正确做法是让两条证据链交汇，而不是争辩「到底该只看相对提升还是只看绝对跑分」。

## 4. 会后为什么如此受打击：真正没有被回应的期待

负责人会后和朋友的讨论中，出现了「是不是太菜了」「方向不对」「思维惯性」「没能切换到另一个角度」等自我怀疑。经过几轮澄清，他明确表示：

1. 最受打击的**不是模型绝对性能不高**，尽管这个缺点客观存在；
2. 也不是导师要求扩大训练和做论文对标本身；
3. 而是**自己最想展示的独立思考与方法设计能力，没有被真正讨论、理解和认可**。

这一点和个人过去的科研不安全感有关：曾把同龄人的研究比成「经过正规训练、有范式和流水线的钢琴手」，把自己比成「主要凭直觉弹奏的钢琴手」。此次汇报不顺，使人很容易把一次特定情境下的交流挫折，扩大成对整体科研能力、思考范式和未来研究方向的怀疑。

应保留当时感受，但避免由情绪直接推出科学结论：**没有被导师立即理解 ≠ 研究毫无方法价值；导师要求高绝对性能 ≠ 他否定研究构思；沟通失败 ≠ 整条研究史无效。** 另一方面，强烈相信自己有方法思想，也不能取代对物理、数据、真实域弱点的检验。

这次挫折的核心不只是「PPT 讲得不清楚」。图表和讲述方式确有改进空间，但还存在真实的**研究优先级与评价框架差异**；仅仅把它归咎于讲演技巧，会再次错过这次反思最有价值的地方。

## 5. 与 AI 的对话如何一步步纠偏：把误解也保留下来

这份复盘不是事后编造的顺利成长故事。会后 AI 的理解经历了多次被负责人修正的过程，值得记录：

1. **初始理解偏差：** AI 先以为主要是导师未听懂创新点、我汇报表达失败，倾向于提供「怎样讲明白方法」的建议。
2. **第一次明确纠正：** 我说「不是，我表达的是机器学习算法优化、流程设计，但他注重的是绝对性能、能不能应用」，并指出他只知道用了优化手段，没有理解具体优化。
3. **第二次纠正：** 当 AI 反复问「是性能低让你受打击，还是方法没被理解」，我明确选了**后者**。这将「研究失败焦虑」与「研究价值没有被讨论的失落」区分开。
4. **补充具体场景：** 我解释自己按 PDF 先讲方法创新，再讲五类扰动、数据集，导师却追问温度、成分、公式与材料物理是否对应；随后又侧重前人论文的绝对性能。
5. **补充柱状图细节：** 导师起初误解成比较前人原模型；我纠正说比较的是前人原方法；他接着问是否有 bias，并要求更高跑分和真实数据检验来建立 trust。
6. **最终理解：** 「思考角度不同」不是抽象的性格差异、简单的传统科研与 AI 科研对立，更不是「导师不懂机器学习」。它同时涉及**问题入口、抽象层级、证据的逻辑起点、工作成果被评价的单位，以及导师/学生对本次汇报想获得什么的不同期待**。

对 AI 本身的教训：不要过早把科研挫败心理化，也不要轻易替导师下「懂不懂 ML」「看不起方法」的判断；应当先还原每个问答的研究对象、双方各自使用的比较基准和实际说过的话，再解释情绪反应。

## 6. 不应混为一谈的三种科研可信度

**A. 物理/任务有效性（physical or task validity）**  
给定材料结构、测量过程和真实实验条件后，模拟器是否提供具有物理意义的数据？扰动是否保持标签？哪些因素（温度、成分、相变、多相等）超出任务边界？这决定研究问题的科学前提。

**B. 方法内部有效性（internal method validity）**  
在明确任务和受控协议里，额外使用 parent provenance 的 JS 训练相比 ERM 是否有边际收益？改变的究竟是监督关系还是同时改变了数据暴露、架构、计算预算或其他混杂因素？这决定「方法改善」的因果说服力。

**C. 外部/应用有效性（external validity and practical credibility）**  
绝对 Macro-F1/Accuracy 是否足够？真实测量谱上表现如何？与已发表工作是否在真正可比条件下具有竞争力？这决定对外说服力与部署可能性。

**三者缺一不可，但不是同一个问题。** 内部方法有效≠现实中够好；现实中跑分高≠所声称的方法机制有效；物理扰动有出处≠已经覆盖全部材料条件。

## 7. 下一轮科研和汇报应如何真正吸收教训

这里记录的是**设计准则和下一阶段讨论意向**，不是未经预注册就修改已冻结论文协议的命令。

1. **开篇先讲真实任务与物理边界**：PXRD 七晶系识别要面对什么现实测量变化；列清现有五扰动的物理锚点、理想化和未覆盖因素；明确温度/成分何时可保持标签、何时改变标签或对象。
2. **再讲已有领域工作的绝对性能与比较口径**：优先使用任务真正对应的数据集、split、指标。不同论文不可比时直说；不能为了数字漂亮而偷换 benchmark。
3. **展示当前模型自身的绝对表现，不隐藏真实域弱点**：尤其清楚区分模拟域、RRUFF few-shot 与 CNRS zero-shot，不能把不同现实域的分数混成一种泛化结论。
4. **然后展示自己的方法贡献**：用结构来源 → 同源不同谱 → 额外关系监督的示意图，说明为什么不是「简单换个 loss」或发明 JS。
5. **方法比较图写清身份与控制变量**：前人提出的方法、我们自己按统一设置复现的 baseline、他人原模型、跨论文参考分数绝不混称；对可能存在的 bias 给出实质回答。
6. **若扩大训练规模**：可按导师建议，考虑在更大结构集上**同时扩展 ERM 和 JS**，确认方法增益是否继续存在，同时研究绝对性能与公平外部 benchmark。需要独立协议、明确训练预算、数据泄漏审查与真实性验证；不能改写当前 frozen Test/历史结果。
7. **把跨领域视角发展为能力，而不是丢掉其中一边**：既能设计可迁移 ML 监督与流程，也能回应科学测量者最基本的「这些输入和标签代表真实世界什么」的问题。

关于后续方向：负责人在本次汇报前后进一步倾向于**优先继续 PXRD 晶系分类、扩大数据规模并尝试与现有论文对标**，而不是立即让定量参数反演分支挤占主线。这是当时的路线偏好，需要在实际新实验开始时由独立协议和更新的当前状态落地；本文不宣称新增 benchmark 已完成。

## 8. 对项目发展心路历程与未来申请的重要性

这次不是一个「导师一句话让我突然懂得应该堆数据」的简单故事，而是一个更有层次的认知转折：

- **此前**，研究兴趣逐渐从 FerroAI 和常规 Materials ML 流程，发展到利用 PXRD 的物理可模拟性，探索监督关系、实验设计和 ML 方法改进；长期倾向 AI for scientific characterization / scientific measurement，而非湿实验。
- **研究过程中**，经历方法扩张、Residual 退出、PAMPT backbone 诊断与 ResNet 更替，再到 same-parent JS 控制实验、真实域验证与数据效率补充，逐步学会聚焦可证伪的具体研究主张。
- **2026-10-22 晚**，首次如此鲜明地感受到：从「我的方法为什么比 baseline 好」到「为什么说这个材料测量模型真实且可信」之间，存在自己此前低估的解释与证据鸿沟。
- **接下来要发展**的不是放弃方法兴趣、单纯追求绝对性能，而是建立跨越两种问题入口的能力：**在物理上界定问题，在方法上提出新监督，在实验上验证边际贡献，在领域基准和真实数据上说明应用边界。**

未来写申请材料应如实描述「思考和证据观念如何改变」，不美化一次受挫的汇报为已经解决的突破；不把导师的指导改写成对方认可了自己的方法创新，也不把当时的失落编造成个人能力不行的证据。可以强调：这次经历使我更明确希望继续研究**机器学习方法与科学测量之间的接口**，并更加重视跨学科沟通、测量物理与外部基准。
