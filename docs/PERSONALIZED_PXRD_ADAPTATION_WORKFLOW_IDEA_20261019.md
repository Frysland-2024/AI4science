# 2026-10-19 idea note: personalized PXRD adaptation workflow / materials archive

> **Status: DISCUSSION / UNVALIDATED / NOT AN APPROVED EXPERIMENT.** This is a dated record of the researcher's own proposal, not evidence of completed software, model performance, domain adaptation, external data licensing, or commercial originality. Leave frozen JS classification results, failed factorization attempts, and existing inversion protocols unchanged.

## Where this idea came from

The completed PXRD classification line studied how simulator-retained *same-parent* provenance provides additional supervision for seven-crystal-system predictions. Its RRUFF few-shot experiment provided experience with simulation-to-experiment adaptation. The separate inversion attempts (direct supervised parameter regression, forward reconstruction loss, structure/measurement factorization, and DONUT-style self-supervision) exposed difficulties when choosing network architectures before understanding the conventional expert PXRD indexing/refinement workflow. Related-work review of classical refinement software, WPEM/CrystalShift, RAPID-like neural initializers, and automated XRD analysis pipelines motivated a narrower role for ML: assist rather than replace physics-based fitting.

The 2026-10-18 proposal in `FERROELECTRIC_PRE_REFINEMENT_12W_PLAN.md` considered one material family with human-provided candidate CIF templates and Top-K conditional initial values. A subsequent discussion emphasized **a reusable, domain-specific training workflow** instead of a single trained model; the RRUFF database was proposed as a public-data pilot, subject to audit of *paired raw experimental patterns and trustworthy experimental lattice-parameter references* by mineral family.

## New idea explicitly proposed by the researcher (2026-10-19)

What is delivered is **not a universal crystal parameter predictor, but a reusable mechanism for configuring, generating, training, adapting, evaluating, and archiving a custom PXRD model for an individual laboratory/material family**.

Conceptual flow:

1. **User/lab registry and persistent materials archive.** The user provides the material family, composition range, plausible phases or candidate structures, instrument metadata, and existing refined experimental cases. Save a scoped versioned project/model/data record; keep ownership and access boundaries.
2. **Approved data acquisition via the Materials Project API** (and/or curated CIF from other licensed or authorized sources). Retrieve structures and provenance. **MP returns structure records; synthetic training PXRD still has to be generated by a valid diffraction simulator**, including measured-domain nuisance factors. Do not blindly web-scrape or assume MP cell parameters are experimental refinement ground truth. Record MP IDs, source versions, licensing/usage checks, timestamps and hashes.
3. **Domain-specific simulation.** Material-family constraints, candidate CIF, allowed lattice-parameter range, symmetry, wavelength, background, peak width, noise, texture, and other validated nuisance factors. Avoid assuming all proposed material states or perturbation ranges are physically realistic.
4. **Train/reuse an initial model** to predict phase-conditional lattice-parameter initial values (or measurement nuisance parameters when appropriate) rather than replace refinement. Use cheap standardized backbones/baselines first.
5. **Target-lab adaptation** using a small collection of *separate* real experimental PXRD and reference refinements. If labels are scarce, consider freezing most parameters, small adapters, simulator/instrument calibration, or physics-based estimation instead of unconditional full fine-tuning. Distinguish material-family shift from instrument/sample-preparation shift.
6. **Inference plus physics refinement.** For a new real PXRD scan, return phase hypotheses / parameter initial values and a fitting/uncertainty report. Run a standard numerical refinement; report invalid-model/mixture/unknown cases for human judgment.
7. **Archive and version results.** Preserve training-data provenance, user/lab metadata, model and code version, validation split, reference fitting protocol, failed cases, and any approved per-user updates. Do not pool user data without consent.

## Candidate scientific question (to be tested)

> For a fixed domain-specific PXRD family and expert candidate structure set, does reproducible simulator pretraining followed by limited target-lab adaptation produce initial values that improve the **end-to-end** success rate/time/stability of classical refinement relative to (i) default/reference CIF initialization, (ii) physics-only multistart, and (iii) synthetic-only NN initialization?

Research must explicitly isolate whether improvement comes from domain-specific prior/simulator coverage, from any real-label adaptation, or merely from a changed refinement budget.

## Boundaries and failure risks

- **Workflow/platform novelty is not automatically algorithm novelty.** AutoML, per-client model customization, simulation-based training and domain adaptation all have precedent. Any new scientific claim needs a precise baseline and evidence.
- Two or three real reference spectra may be too few for reliable neural fine-tuning and independent evaluation. Some real refinements are model-dependent estimates, not absolute structural ground truth; do not use the same case for adaptation and independent claims.
- A user-specific model does not always need to be trained from scratch; family-level reusable models and instrument-specific calibration may be cheaper and more reliable.
- A material family may have multiple competing polymorphs, structural disorder or mixtures not represented by a CIF or simplistic forward model. Need honest out-of-scope/fail behavior.
- User-uploaded measurements may be confidential; store under explicit user control, scoped access, documented retention/deletion, and separate tenant boundaries.
- Resource costs matter: MP querying, diffraction simulation, per-user training/inference, storage and reproducibility. Use official API and honor provider policies.

## Minimum thesis-sized validation / stop condition

**Do NOT build the full account system or automatic per-user model marketplace now.** First: 
- Audit RRUFF sample-level pairing of raw PXRD / refinement cell parameters / structure templates and decide if any mineral family has enough *independent* data for adaptation and held-out evaluation.
- Run a single-family, one-parameter (e.g. cubic lattice a) pilot: simulator → ordinary regression network → optional limited domain adaptation → NN initial value → identical classical refinement.
- Compare against source-CIF and strong multistart physics-only baselines; measure real-label cost, parameter error *when defensible*, convergence, residual and all-in wall clock.
- If limited real labels or a saturated physics baseline make adaptation benefit untestable, report LIMITED_GO/NO_GO and retain this as a long-term platform vision.
- Only after the single-family scientific gate, consider a second family to evaluate reusability. An interactive archive, MP API connector, user accounts and generalized routing are future product engineering, not required for the first undergraduate thesis.
